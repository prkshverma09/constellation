 Scope and acceptance criteria
 The product is done when a judge can perform the following journey live, unassisted, in under two minutes, and the second journey shows an honest gap.
 Journey A — supported path (STXBP1)
 Type STXBP1 , Munc18-1 , DEE4 or STXBP1 Foundation ; all resolve to MONDO:0012812 with the synonym shown.
 Overview shows counts with links: HPO terms, ClinVar pathogenic variants, trials, active NIH projects, papers, exact-match community.
 Cluster view lists DNM1, SNAP25, STX1B, VAMP2 as supported neighbours with the mechanism label, and GNAO1 in a counterexample lane with the layer that excluded it.
 Any edge opens an inspector: source, retrieval date, relationship type, evidence class, confidence, contradicting evidence.
 Asset view compares NCT06555965 against DNM1-DEE: matches, differences, expert checks.
 People view shows at least one investigator with edges to both STXBP1 and DNM1 and the proving paper or award.
 Dossier renders with every sentence footnoted to an edge ID; export produces a PDF via print styles and a Markdown file.
 Persona switch to Priya (mechanism in → ranked clusters) and Devon (plain language) re-renders without a new query.
 Journey B — honest gap (FRRS1L or equivalent)
 Search resolves the disease and shows the sparse counts honestly.
 Cluster view says no supported neighbour meets the threshold, lists the nearest unsupported leads and which layer is missing for each.
 Coverage panel lists sources queried, term sets, counts and dates.
 Dossier is replaced by a "what would change this" plan: the specific evidence (for example a functional study classifying the variant effect) and where it would come from.
 Non-goals for the 24 hours. No user accounts, no write-back to public databases, no general chat. Anything not in the dossier template or the two journeys is cut at feature freeze (H18).

 OpenAI usage: extraction, reconciliation, agents
 Extraction (GPT-5 mini, Structured Outputs, Batch API)
 One batch job per schema. Input: PMID, title, abstract, the gene list for the slice. Output must satisfy the strict schema below; anything else is a rejected row.
 class Claim(BaseModel):
 subject_gene: Literal[*SLICE_GENES]
 claim_type: Literal["mechanism", "variant_effect",
 "phenotype", "model", "therapy"]
 object_text: str # free text, reconciled later
 object_hint_id: str | None # e.g. "HP:0001250" if the model is sure
 polarity: Literal["supports", "contradicts"]
 quote: str # verbatim; validator requires substring match
 confidence: float # 0..1
 evidence_level: Literal["in_vitro", "animal", "human_case",
 "human_cohort", "review"]
class ExtractionResult(BaseModel):
 pmid: str
 claims: list[Claim] # may be empty
 investigator_roles: list[InvestigatorRole] # first/last author flags
 Two further schemas: OutcomeMeasureMapping (measure text → HP terms + domain) and EligibilityFacts (age range, genotype requirement, variant classes, exclusions). Variant-effect claims across papers for a gene are aggregated by majority with the dissenting PMIDs kept as contradicts edges.
 Reconciliation (GPT-5 + text-embedding-3-small)
 Diseases and phenotypes. Free-text mentions are embedded and matched against Monarch search results for the same text; GPT-5 chooses among the top five candidate CURIEs or returns none . The model never emits an ID that was not in the candidate list.
 People. Blocking on normalised surname + first initial; GPT-5 decides merges using affiliations, co-authors, project→publication links from RePORTER, and gene overlap. Merge decisions are stored with the reason so the people view can show "same person because…".
 Organisations. Web-discovered names are matched to seed-list entries by domain; otherwise a new PatientGroup is created with verified_on .

 Analytics
 Fused similarity
 For two slice diseases \(d_i, d_j\) with causal genes \(g_i, g_j\):
 P = semsim(d_i, d_j) / max semsim within slice # phenotype, 0..1
M = max( jaccard(reactome_lowest_level(g_i), reactome_lowest_level(g_j)),
 1.0 if STRING(g_i, g_j) >= 0.7 else 0 ) # mechanism, 0..1
V = 1.0 if same variant class
 else 0.5 if either class unknown
 else 0.0 # variant effect
S = 0.5*P + 0.3*M + 0.2*V
edge shares_mechanism_with if S >= 0.45 AND M > 0 # phenotype alone never suffices
 The M > 0 guard is what turns "DEE 17 looks closest by symptoms" into a counterexample rather than a neighbour. Weights are recorded on every analytics edge and exposed in the README; the UI shows the three layer scores, not just S.
 Clustering and counterexamples
 Leiden (leidenalg, modularity objective) on the weighted shares_mechanism_with graph, resolution swept 0.6–1.4 in steps of 0.1, 20 seeds each. Choose the lowest resolution at which the mean pairwise adjusted Rand index across seeds is ≥ 0.8; record resolution, seed and stability on each Cluster node.
 Cluster label: GPT-5 names the cluster from its shared Reactome pathways and STRING complex, constrained to the pathway vocabulary ("presynaptic vesicle cycle — SNARE/Munc18").
 Counterexample per cluster: the non-member with the highest P against any member; displayed with the layer that excluded it (M = 0, or V = 0).
 Golden test: STXBP1's cluster must contain DNM1 and at least two of SNAP25, STX1B, VAMP2, and must not contain GNAO1, GABRG2 or KCNT1. If the sweep cannot satisfy this, the weights are wrong, not the test; investigate before touching the test.
 Bridge people
 Candidate set for clusters (or diseases) A and B: persons with at least one authored , investigates or funds -derived edge to a member of A and one to a member of B.
 Rank by min(n_A, n_B) , then by betweenness centrality on the person–disease bipartite subgraph induced by A ∪ B, then by recency.
 Each card shows the proving edges (paper title and year, study NCT, award number). No contact details beyond public affiliation and the CT.gov central contact if listed.
 Precision check at H16: 20 top-ranked bridges hand-checked by D; target ≥ 0.8 are genuine same-person bridges.
 Asset coverage
 For a study asset and a neighbour disease: coverage = information-content-weighted fraction of the neighbour's HPO terms (frequency ≥ occasional) that are ancestors-or-equal to any HP term mapped from the study's outcome measures.
 Differences table from EligibilityFacts : age window, genotype requirement, variant classes accepted, exclusions — each row marked "matches", "differs" or "needs expert review" (the last whenever VariantClass differs or is unknown).
 The demo claim "ENDD outcome measures cover ~80% of DNM1's phenotype" is computed, not typed; whatever the number is, it is shown with its denominator.
 Honest-gap detector
 Gap if: no neighbour with S ≥ 0.45, or cluster has no Asset and no bridge Person.
 Coverage report lists each source, the query terms, record counts, retrieval dates, and the nearest three leads with the missing layer named.
 "What would change this" is templated per missing layer: missing M → functional or pathway study; missing V → variant classification study; missing asset → the nearest study whose protocol could be adapted; missing people → the nearest cluster's bridge investigators as cold-start contacts.

 Risks and fallbacks
 Batch API latency. Batch jobs can take hours. Mitigation: submit the first 500 abstracts at H3 and the rest in four chunks by H6; if any chunk is not back by H9, run it synchronously with GPT-5 mini at 20 concurrent requests (~25 minutes).
 Cluster does not match the biology. If the Leiden sweep cannot satisfy the golden test, inspect the three layers for STXBP1–DNM1 first (Reactome may place them in different lowest-level pathways; STRING should still link SNARE partners). Adjust weights once, document why, and never special-case gene names.
 Person reconciliation noise. Common surnames produce false merges. Mitigation: require two signals (affiliation or co-author or RePORTER publication link) for a merge; show "why same person"; the demo bridge is hand-verified at H16.
 Public API outage during judging. All reads come from the committed snapshot; identifier links point to public pages, not live calls. The dossier for both demo diseases is cached. The app has no runtime dependency on any external API in LLM_MODE=cached .
 Over-claiming biology. Every mechanistic sentence is labelled with its evidence class and level (in vitro, animal, human); the Skeptic's objections appear in the dossier, not a hidden log; the README states that the atlas proposes, clinicians decide.
 Scope creep. The dossier template and the two journeys are the spec. The feature-freeze checkpoint at H18 is owned by D and is not negotiable; stretch items are listed in priority order and taken only from the top.
